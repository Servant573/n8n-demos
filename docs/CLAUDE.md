# Инструкция для Claude Code (и других AI-ассистентов)

Этот файл — точка входа для AI, который будет помогать разработчику довести проект `n8n-demos` до рабочего состояния. Читай внимательно, следуй порядку, задавай вопросы когда неясно.

## Что это за проект

`n8n-demos` — демонстрация возможностей N8N + локальных LLM в контексте IT-компании, разрабатывающей платформу для логистики и ритейла. Демо — рабочий стенд, который можно запустить и показать руководству или клиентам.

**Главная особенность:** проект намеренно оставлен как **заготовка**. Вся инфраструктура, моки, seed-данные готовы. Воркфлоу N8N оставлены в виде JSON-заготовок с полной спецификацией внутри (поля `_spec`). Твоя задача — собрать их в N8N UI по спецификации и протестировать.

## Почему воркфлоу не сгенерированы целиком

N8N-воркфлоу — это большие JSON-структуры с ID нод, позициями на canvas, привязкой credentials. Генерировать их "на сухую" без N8N-инстанса рискованно: часто не импортируются из-за несоответствия версии, битых ссылок на credentials, изменившихся параметров нод.

Правильный путь — собрать в UI, потом экспортировать в JSON и положить в `workflows/`. Спецификации внутри `_spec` — пошаговый план, по которому это делается.

### Шаг 1 — Подними инфраструктуру и убедись, что всё работает

```bash
cp .env.example .env
# отредактируй N8N_ENCRYPTION_KEY в .env (любая строка 32+ символов)
docker compose up -d
docker compose logs -f ollama-bootstrap
# жди пока не увидишь "All models ready" (может занять 10-15 минут на первом запуске)
```

Проверь:
- `curl http://localhost:5678` — N8N UI отвечает
- `curl http://localhost:8065` — Mattermost отвечает
- `curl http://localhost:11434/api/tags` — Ollama показывает скачанные модели
- `psql -h localhost -U demo -d demo -c "\dn"` — видны схемы cve_watcher, logistics_assistant

Если что-то не отвечает — чини инфру, не переходи дальше.

### Шаг 2 — Доведи демо до конца

Для каждого демо:

6. Пройди "Критерии успеха" из README — все галочки должны стоять

## Ключевые правила при работе

### Правило 1 — Читай спецификации, не изобретай

Во всех `_spec` уже продуман каждый шаг, включая выбор нод, параметры и fallback'и. Если есть соблазн сделать "по-другому" — сначала пойми, почему написано именно так.

### Правило 2 — Не вызывай внешние LLM без явного разрешения

Вся инфраструктура заточена под **локальные модели через Ollama**. Клиент выбрал их осознанно: дёшево, в контуре, без блокировок.

**Не добавляй** вызовы Claude/OpenAI «для качества», если разработчик этого не попросил.

### Правило 3 — Mattermost, а не Telegram

В компании клиента заблокирован Telegram. Везде, где в спецификации написано "Mattermost" — именно Mattermost, не Telegram.

### Правило 4 — Не создавай файлы, которых нет в плане

Структура проекта продумана. Перед созданием новых файлов:
- Загляни в `README.md` корня проекта — там вся раскладка
- Если добавляешь что-то полезное — обнови раскладку в README

## Частые задачи и как их решать

### Задача: "Собери воркфлоу N8N по спецификации"

1. Открой `_spec` из JSON-заготовки
2. Открой N8N UI: http://localhost:5678
3. New workflow -> задай имя точно как в `_spec.name`
4. По очереди добавляй ноды, соединяй стрелками
5. Для Code-нод копируй JS из `snippets/SNIPPETS.md`
6. Для HTTP Request — бери URL и body из `_spec`
7. Для credentials (Postgres, Ollama, Mattermost) — настраивай один раз, потом переиспользуй
8. Запусти вручную (Execute Workflow), проверь каждую ноду
9. Экспортируй: меню -> Download -> сохрани в `workflows/` с тем же именем

### Задача: "Воркфлоу падает на вызове LLM"

Типичные причины:
- **Модель не скачалась.** Проверь `curl http://localhost:11434/api/tags` — должна быть `qwen2.5:7b`.
- **Timeout.** Первый вызов LLM после старта Ollama — медленный (модель загружается в память). Подними timeout в HTTP-ноде до 60 секунд.
- **Битый JSON.** Модель иногда выдаёт преамбулу ("Вот ваш JSON:..."). Лечится `format: "json"` в body и низкой температурой (`temperature: 0.2`).

### Задача: "Как протестировать без N8N"

Все компоненты можно дёргать напрямую:
- Ollama: `curl http://localhost:11434/api/generate -d '{"model":"qwen2.5:7b","prompt":"Привет","stream":false}'`
- Mattermost: настроить через web UI http://localhost:8065

## Что НЕ делать

- Не коммить `.env` с реальными токенами
- Не захардкоживай API-ключи в воркфлоу JSON (используй credentials)
- Не добавляй новые сервисы в docker-compose без обсуждения — проект и так тяжёлый по памяти
- Не переписывай init-db.sql, если только не добавляешь новое демо — это сломает существующие
- Не включай воркфлоу по расписанию в демо-версии — они должны запускаться вручную для наглядности
- Не используй production URL'ы (claude.ai, openai.com) без явного разрешения
